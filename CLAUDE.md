# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

MeetingMinder (product name in the UI: "Echo Ledger") records meetings on an Android phone,
transcribes them in ~10s chunks, and produces per-meeting summaries plus a daily roll-up.

It began as a Manus WebDev app and was detached into a standalone **Capacitor Android** app.
There is no server, no accounts, and no cloud database: everything is stored in on-device
SQLite. The only network calls are to the OpenAI API, using a key the user supplies.

Commit `cc593b8` holds the original flattened Manus snapshot if you need to compare against
the pre-migration behaviour.

```bash
npm run dev          # Vite dev server; SQLite runs via jeep-sqlite/wasm in the browser
npm run build        # tsc -b && vite build
npm run typecheck    # tsc --noEmit
npm test             # vitest run
npm test -- -t "partial summary"   # single test by name
npm run db:generate  # regenerate SQL migrations after editing src/lib/schema.ts
npm run sync         # build + cap sync android
npm run android      # sync + open Android Studio
```

Gradle needs a JDK. Android Studio's bundled one works:

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
cd android && ./gradlew assembleDebug     # -> android/app/build/outputs/apk/debug/
```

Note that piping Gradle to `tail` masks its exit code — check `${PIPESTATUS[0]}` or redirect
to a file if you need to know whether it actually succeeded.

## Architecture

**No server.** React pages call `src/services/*` directly; TanStack Query (`src/lib/queries.ts`)
provides caching and invalidation only, with no network client underneath. `src/services/meetings.ts`
is a local reimplementation of what used to be a tRPC router — the Manus original was never
part of the export, and its contract was reconstructed from the client call sites and the
lifecycle test.

**Persistence** is Drizzle over `@capacitor-community/sqlite` via the `sqlite-proxy` driver
(`src/lib/sqlite.ts`). Migrations are generated by drizzle-kit into `./drizzle` and applied on
first connection. Two things about that driver are worth knowing before you touch it:

- It has **no transaction support**, so `withTransaction()` drives `BEGIN`/`COMMIT`/`ROLLBACK`
  on the shared connection. It is not re-entrant-safe by nature; a guard makes nested calls
  join the enclosing transaction rather than fail.
- It expects rows as **positional arrays**, but Capacitor SQLite returns column-keyed objects.
  The bridge is `Object.values(row)`, which relies on key order matching `SELECT` order. It
  does — but a query selecting two identically-named columns (an unaliased join) would break
  it in a confusing way. Nothing currently does that.

`PRAGMA foreign_keys = ON` runs on every connection. SQLite defaults it off, which would
silently disable every `ON DELETE CASCADE` in the schema.

**Single user by construction.** There is no `users` table and no `userId` column. The Manus
build scoped every query by `userId`; the OS sandbox provides that guarantee now. Don't
reintroduce user scoping without a reason.

**OpenAI.** `src/lib/openai.ts` (chat completions, for summaries) and `src/lib/transcription.ts`
(Whisper). The key lives in Capacitor Preferences via `src/lib/settings.ts` and gates the whole
app — `ApiKeySetup` replaced the old sign-in screen.

## The recording pipeline

`src/hooks/useMeetingRecorder.ts` is the most intricate file in the repo.

1. It does **not** use MediaRecorder's timeslice. It starts a fresh `MediaRecorder` per 10s
   chunk, stops it, and starts another, so each chunk is a standalone decodable container.
   `recorderCycleRef` is a generation counter that cancels stale async continuations after a
   stop or split.
2. Chunks are sent to OpenAI as `Blob`s in multipart form data. Failures land in
   `failedChunksRef` keyed `meetingId:sequence` and are replayable via `retryFailedChunks()`.
   This subsystem is load-bearing — chunks cross a network boundary and mobile connections drop.
3. `startAudioAnalysis` computes RMS per animation frame; when `shouldSplitForSilence`
   (`src/shared/segmentation.ts`, pure and unit-testable) fires, the client splits the meeting
   atomically and keeps recording.
4. Server-side segment numbering is `chunkSequence * 1000 + index` — sparse, so segments stay
   globally ordered without renumbering earlier chunks.
5. On stop or split, `summarizeAfterUploads` waits for in-flight chunks, then summarizes the
   meeting and rebuilds that day's roll-up.

## Android constraints

**This build records only while foregrounded.** The silence detector runs on
`requestAnimationFrame`, which halts entirely when the screen sleeps, and chunk rotation uses
`setTimeout`, which Android throttles in the background. A screen wake lock is therefore
load-bearing, not a nicety, and it is re-acquired on `visibilitychange` because Android drops
it whenever the page is hidden.

Background recording requires a native foreground service with
`foregroundServiceType="microphone"` (mandatory from Android 14) and a persistent notification.
That is **deliberately deferred** until the foreground MVP proves out. Implementing it means
moving capture and RMS analysis into Kotlin; the JS design ports, the implementation does not.

`chooseMimeType()` picks from a candidate list and may resolve to `audio/mp4` rather than
`audio/webm` on some devices — that path has not been exercised on real hardware yet.

The manifest strips `USE_BIOMETRIC`/`USE_FINGERPRINT`, which the SQLite plugin declares for an
encryption feature this app disables.

## Invariants worth preserving

- **No partial summaries.** If any audio chunk is not `completed`, summarization throws
  `CONFLICT` and marks the meeting `failed` rather than summarizing half a conversation. The
  single exception is `isIgnorableTerminalAudioFragment` (`src/shared/audioChunk.ts`): a final
  chunk that is tiny (<1 KB), short (≤3 s), failed on a decode error, and follows at least one
  success is recorder-teardown noise and does not block.
- **Repair on read.** Opening a stuck `processing` meeting re-derives its true state from chunk
  statuses and persists `failed`. `getMeetingDetail` is a repair point, not just a getter.
- **Audio is transient.** `purgeMeetingProcessingArtifacts` deletes chunks and segments *after*
  the summary is durable — never before, since the transcript is the only thing that makes a
  retry possible. This is the product's core privacy claim and the UI copy states it.
- **Summaries must not hallucinate.** Both summary services use strict `json_schema` responses
  plus a prompt forbidding invented owners, dates or commitments, and validate with Zod after
  parsing. `dailySummary.ts` degrades to `buildDailySummaryFallback` (mechanical, no LLM) on any
  error, and always sources `actionItems` from the fallback rather than the model.
- **`whisper-1` is not interchangeable.** It is the only transcription model supporting
  `response_format: verbose_json`, and the transcript timeline is built entirely from the
  per-segment timestamps only that format returns. `gpt-4o-transcribe` is cheaper and would
  silently destroy the feature.
- Timestamps are epoch-ms `integer` columns named `*AtMs`.

## Testing

Vitest, no DOM environment needed. `src/services/meetings.lifecycle.test.ts` mocks `@/lib/db`
and both summary generators outright — this keeps the test on lifecycle logic and stops the
import chain dragging in Capacitor and SQLite. Mock factories must be declared before the
`await import()` of the module under test.
